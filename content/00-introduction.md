# 소개

## OpenCode Harness 입문

OpenCode를 단순 코드 생성 도구로만 사용하면 agent가 요구사항을 추측하거나, 구현 범위를 넓히거나, 검증을 빠뜨릴 수 있습니다. Harness는 이런 문제를 줄이기 위해 프로젝트 문서, 작업 규칙, phase 실행 흐름, 안전 hook을 하나의 운영 구조로 묶습니다.

이 강의에서는 `build-opencode-harness` skill이 만드는 구조를 기준으로 OpenCode를 프로젝트에 적용하는 방법을 배웁니다.

## 이 강의에서 배우는 것

이 강의의 Harness 구조는 하나의 예시입니다. 그대로 복사해서 쓰기보다, 각자의 개발 방식, 프로젝트 구조, 팀 규칙에 맞게 튜닝하는 것을 전제로 합니다.

최종 목표는 다음 요소가 함께 작동하는 방식을 이해하는 것입니다.

- `docs/`: 프로젝트 지식과 장기 기억
- `AGENTS.md`: agent가 먼저 읽는 프로젝트 작업 규칙
- `.opencode/skills/`: 프로젝트 안에서 재사용할 작업 절차
- `scripts/execute.py`: phase 실행과 상태를 관리하는 runner
- `scripts/hooks/`: 위험한 실행 흐름을 막는 안전장치
- `phases/`: 승인 가능한 작은 작업 단위

## Harness가 필요한 이유

Agent에게 일을 맡길수록 중요한 것은 "무엇을 시킬지"보다 "어떤 기준으로 판단하게 할지"입니다. 기준이 없으면 agent는 좋은 의도로 범위를 확장하고, 익숙한 패턴을 새로 만들고, 검증 없이 완료를 선언할 수 있습니다.

Harness는 이 흐름을 반대로 만듭니다.

1. 먼저 문서로 요구사항과 제외 범위를 정합니다.
2. 작업을 phase로 나누고 완료 기준을 씁니다.
3. 사용자가 phase 설계를 승인합니다.
4. Agent는 승인된 범위 안에서만 작업합니다.
5. 검증과 review를 거쳐 다음 phase로 넘어갑니다.

이 강의에서 계속 반복할 메시지는 단순합니다. OpenCode Harness는 agent를 빠르게 움직이게 하는 장치가 아니라, agent가 엉뚱한 방향으로 빠지지 않게 하는 작업 레일입니다.
